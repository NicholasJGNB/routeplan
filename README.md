# 🚇 公交地铁换乘规划算法 · 网页互动讲解

一个**零依赖、纯前端**的交互式可视化页面，用一张小地铁网 + 时刻表，**一步一步、动画式**地讲清楚业界最常用的四种公交/地铁换乘规划算法。

直接用浏览器打开 `index.html` 即可，无需任何构建步骤。

## 为什么坐车的算法和走路 / 开车不一样？

- **有时刻表，要等车**：代价不是「距离」，而是**到达时刻**（含等车时间）。
- **换乘很贵**：通常同时优化「几点到」和「换乘几次」——多目标（帕累托）最优。
- **查询要快**：一座城市几千站、几十万班次，点一下就要出结果。

## 它讲了哪四种算法

| 算法 | 一句话理解 | 关键词 |
|------|-----------|--------|
| **时间依赖 Dijkstra** | 把地铁网当带时刻表的图，每次扩展当前最早能到的站 | 经典基线、保证最优、较慢 |
| **RAPTOR** | 按**轮次**算：第 k 轮 = 最多坐 k 趟车能到哪 | 业界最常用、无优先队列、天然算清换乘次数 |
| **CSA 连接扫描** | 所有区段按发车时刻排队，指针从头扫到尾 | 极简（几十行）、对 CPU 缓存友好 |
| **Transfer Patterns** | 离线预存「站到站最优换乘骨架」，查询时只查表填时刻 | 谷歌地图同款、毫秒级、空间换时间 |

## 怎么玩

1. 左侧**选一个算法**，读它的核心思路；
2. **设定行程**：起点 / 终点 / 出发时刻；
3. 点 **▶ 自动播放** 或 **下一步 ⏭**，跟着右侧解说，看：
   - 地图上各站逐步亮起，并标出**最早到达时刻**；
   - 当前正在处理的站、正在尝试的「坐车 / 步行」边；
   - CSA 还有一条**扫描条**，能看到指针怎么从头扫到尾；
   - 结束时高亮**最终选定行程**，给出到达时刻与换乘次数。

四种算法在同一行程上**结果完全一致**（已对 300+ 组查询交叉验证），但「怎么想出来的」过程截然不同——对比着看最有意思。

## 文件结构

- `index.html` — 页面结构（讲解 + 地图舞台 + 对比卡片）
- `style.css` — 深色地铁风样式与动画
- `script.js` — 网络数据 / 时刻表、四种算法的「录制成步骤」实现、SVG 渲染与播放器

## 示例网络

3 条线（1/2/3 号线）+ 1 处步行换乘通道，8 个站。线路单向，刻意设计出
「1 次换乘 + 步行」优于「2 次换乘」的场景，方便看清算法如何权衡到达时间与换乘次数。
